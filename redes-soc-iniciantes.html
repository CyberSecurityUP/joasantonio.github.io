Fundamentos de Redes
O que são redes, como funciona a comunicação e os conceitos-base que todo analista SOC precisa dominar.
🌐
O que é uma Rede?

Uma rede de computadores é um conjunto de dispositivos (hosts) interconectados que trocam dados entre si. Essa comunicação segue regras chamadas protocolos.

Para o analista SOC, entender redes é entender onde os ataques acontecem — 90% das intrusões passam pela rede.

Host Protocolo Pacote Tráfego
🖥️
Tipos de Rede
  • ◈
    LAN (Local Area Network) — Rede local, dentro de um escritório ou data center. Velocidade alta, baixa latência.
  • ◈
    WAN (Wide Area Network) — Rede de longa distância. A Internet é a maior WAN do mundo.
  • ◈
    MAN (Metropolitan) — Cobre uma cidade ou campus universitário.
  • ◈
    VLAN (Virtual LAN) — Segmentação lógica dentro de uma LAN física. Crítico para segurança!
  • ◈
    DMZ (Demilitarized Zone) — Zona isolada para serviços públicos (web, email). Separa Internet da LAN interna.
🧩
Componentes de Rede
  • ▶
    Switch — Opera na camada 2 (MAC). Interliga dispositivos dentro da mesma LAN.
  • ▶
    Roteador (Router) — Camada 3 (IP). Encaminha pacotes entre redes diferentes.
  • ▶
    Firewall — Filtra tráfego com base em regras. Ponto de controle crítico para SOC.
  • ▶
    IDS/IPS — Detecta/Previne intrusões. Gera alertas que chegam ao SOC.
  • ▶
    Proxy — Intermediário de tráfego. Usado para filtrar, logar e anonimizar.
  • ▶
    WAF — Web Application Firewall. Protege especificamente aplicações web.
📦
Como os Dados São Enviados?

Dados são divididos em pacotes, cada um contendo:

  • →
    Header — Endereços de origem/destino, número de sequência, flags de controle.
  • →
    Payload — Os dados reais sendo transportados (conteúdo da mensagem).
  • →
    Trailer — Verificação de integridade (CRC). Detecta erros na transmissão.
ℹ No SOC, analisar o header dos pacotes revela tentativas de spoofing, scanning de portas e exfiltração de dados.
🔄
Modos de Comunicação
  • ◉
    Unicast — Um para um. Ex: navegação web comum.
  • ◉
    Broadcast — Um para todos na rede. Ex: ARP Request. Pode ser explorado em ataques de amplificação.
  • ◉
    Multicast — Um para grupo específico. Ex: streaming IPTV.
  • ◉
    Anycast — Um para o mais próximo do grupo. Usado em DNS, CDN e DDoS mitigation.
⚠ SOC Alert: Tráfego de broadcast excessivo pode indicar um worm se propagando ou um ataque de ARP Poisoning ativo na rede.

Modelo OSI & TCP/IP
Os dois modelos de referência que explicam como toda comunicação de rede funciona em camadas.
📐
Modelo OSI — 7 Camadas

O modelo OSI (Open Systems Interconnection) divide a comunicação de rede em 7 camadas independentes. Cada camada tem responsabilidade específica e só se comunica com as camadas adjacentes.

# Camada Função & Protocolos
7
Aplicação
Interface com o usuário final
HTTP, HTTPS, DNS, FTP, SMTP, SSH
6
Apresentação
Codificação, compressão, criptografia
SSL/TLS, JPEG, MPEG, ASCII
5
Sessão
Gerencia sessões de comunicação
NetBIOS, RPC, SMB (parcial)
4
Transporte
Entrega fim-a-fim, controle de fluxo
TCP (confiável), UDP (veloz)
3
Rede
Roteamento e endereçamento lógico
IP, ICMP, OSPF, BGP
2
Enlace
Endereçamento físico (MAC), acesso ao meio
Ethernet, ARP, Wi-Fi (802.11)
1
Física
Bits em sinais elétricos/ópticos
Cabos, fibra, ondas de rádio
🔗
Modelo TCP/IP — 4 Camadas (Prático)

O TCP/IP é o modelo real usado na Internet. Colapsa as 7 camadas OSI em 4 camadas práticas:

Camada TCP/IPEquivalente OSIExemplos
Aplicação
5, 6, 7
HTTP, DNS, SSH, SMTP
Transporte
4
TCP, UDP, SCTP
Internet
3
IP, ICMP, ARP
Acesso à Rede
1, 2
Ethernet, Wi-Fi
🤝
TCP Three-Way Handshake

Toda conexão TCP começa com um handshake de 3 vias. Entender isso é fundamental para identificar port scans e sessões suspeitas.

Cliente envia SYN
SYN=1, SEQ=x
Servidor responde SYN-ACK
SYN=1, ACK=1, SEQ=y, ACK=x+1
Cliente confirma ACK
ACK=1, ACK=y+1
Conexão Estabelecida ✓
🚨 SYN Flood Attack: Atacante envia milhares de SYN sem completar o handshake. O servidor esgota recursos esperando ACKs que nunca chegam → DDoS.
🎛️
Flags TCP — O que Significam
FLAGS TCP
# Flags TCP e sua relevância no SOC

SYN  → Inicia conexão            # SYN scan = nmap -sS
ACK  → Confirmação               # Sem SYN = ACK scan furtivo
FIN  → Encerra conexão           # FIN scan bypassa alguns firewalls
RST  → Reset forçado             # Porta fechada ou firewall bloqueando
PSH  → Envio imediato de dados   # Push de payload
URG  → Dados urgentes            # Raro, suspeito se frequente
ECE  → Congestionamento         # Controle de tráfego
CWR  → Congestion Window Reset
⚠ Xmas Scan: Pacote com SYN+FIN+URG+PSH simultâneos. Absurdo no TCP real — indica varredura maliciosa.
📦
Encapsulamento e PDUs

Cada camada adiciona seu próprio cabeçalho ao dado — isso se chama encapsulamento. Cada camada tem sua unidade de dados (PDU):

  • 7
    Dados — Camadas 5-7 (Aplicação)
  • 4
    Segmento — Camada 4 (TCP) ou Datagrama (UDP)
  • 3
    Pacote — Camada 3 (IP)
  • 2
    Frame/Quadro — Camada 2 (Ethernet)
  • 1
    Bits — Camada 1 (Física)

IPs Privados (RFC 1918)

Endereços reservados para uso interno. Nunca roteáveis na Internet pública.

RFC 1918 — Ranges Privados
10.0.0.0/8        # Classe A → 16.777.214 hosts
172.16.0.0/12     # Classe B → 1.048.574 hosts
192.168.0.0/16    # Classe C → 65.534 hosts

# IPs especiais
127.0.0.1         # Loopback (localhost)
169.254.0.0/16    # APIPA (sem DHCP) → suspeito!
0.0.0.0           # Qualquer interface
255.255.255.255   # Broadcast limitado
⚠ Encontrar tráfego de 169.254.x.x em logs indica falha de DHCP. Dispositivos com APIPA podem ser pontos cegos de monitoramento.

IPv6 — O Futuro (e o Presente)

IPv6 tem 128 bits — espaço para 340 undecilhões de endereços. Formato hexadecimal com 8 grupos de 16 bits.

IPv6 — Formatos
# Endereço completo
2001:0db8:85a3:0000:0000:8a2e:0370:7334

# Simplificado (omite zeros)
2001:db8:85a3::8a2e:370:7334

# Loopback IPv6
::1

# Link-Local (equiv. 169.254.x.x)
fe80::/10

# IPs privados (ULA)
fc00::/7
ℹ Muitas organizações ainda não monitoram tráfego IPv6 adequadamente. Atacantes usam isso para tunelamento IPv6-sobre-IPv4 para bypassar controles.
🔀
NAT — Network Address Translation

NAT permite que múltiplos dispositivos com IPs privados compartilhem um único IP público. Fundamental para entender logs de firewall.

  • →
    SNAT — Traduz IP de origem. Saída à Internet (common).
  • →
    DNAT — Traduz IP de destino. Port forwarding para servidores internos.
  • →
    PAT/Masquerade — NAT com porta. Um IP público, muitos hosts internos.

DNS — Domain Name System

DNS traduz nomes (google.com) em IPs. É um protocolo crítico para detecção de ameaças — malwares usam DNS para C2.

Tipos de Registro DNS
A      → hostname para IPv4
AAAA   → hostname para IPv6
MX     → servidor de email
CNAME  → alias (apelido)
NS     → nameserver autoritativo
PTR    → reverse DNS (IP → nome)
TXT    → texto livre (SPF, DKIM)
SOA    → info de zona DNS
🚨 DNS Tunneling: Atacantes exfiltram dados codificando-os em consultas DNS (subdomínios longos/randômicos). Ferramenta: iodine, dnscat2. Detecte via volume anômalo de queries DNS.
🔄
ARP — Address Resolution Protocol

ARP mapeia IPs (camada 3) para MACs (camada 2). Opera apenas na LAN. Protocolo sem autenticação — altamente suscetível a spoofing.

ARP no Linux
$ arp -n
Address         HWtype  HWaddress          Iface
192.168.1.1     ether   aa:bb:cc:dd:ee:ff  eth0
192.168.1.50    ether   11:22:33:44:55:66  eth0

$ ip neigh show  # Alternativa moderna
🚨 ARP Poisoning/Spoofing: Atacante envia ARP Replies falsos, associando seu MAC ao IP do gateway. Resultado: Man-in-the-Middle completo na LAN. Detecte com ARPwatch.
📧
ICMP — Internet Control Message Protocol

ICMP não transporta dados de usuário — transmite mensagens de controle e erro. Base do ping e traceroute.

Tipos ICMP Importantes
Type 0  Echo Reply        # Resposta ao ping
Type 3  Dest Unreachable  # Host/porta inacessível
Type 5  Redirect          # ⚠ Pode ser exploit
Type 8  Echo Request      # O ping
Type 11 TTL Exceeded      # Base do traceroute

# Detectar ICMP Flood (ping of death / smurf)
$ tcpdump icmp
🔐
TLS/SSL — Criptografia de Transporte

TLS criptografa comunicações de rede. Todo analista SOC deve entender seu funcionamento para detectar TLS mal configurado, certificados inválidos e C2 over HTTPS.

  • 🔑
    Handshake TLS — Negocia algoritmos, troca certificados, estabelece chave de sessão.
  • 🔑
    SNI (Server Name Indication) — Informa o hostname no ClientHello. Visível mesmo em tráfego criptografado!
  • 🔑
    Certificate Pinning — App aceita só cert específico. Dificulta MitM e inspeção de proxy.
  • 🔑
    Self-signed certs — Comum em malware C2. Gera alerta no SOC.

Linux para Redes
Comandos fundamentais de rede no Linux. Do diagnóstico ao monitoramento — tudo que um analista SOC usa no dia a dia.
💻
Interfaces de Rede
BASH
# Ver todas as interfaces e endereços IPs
$ ip addr show
$ ip a             # Atalho

# Ver apenas interface específica
$ ip a show eth0

# Legado (ainda encontrado em ambientes)
$ ifconfig
$ ifconfig eth0

# Ver estado das interfaces (up/down)
$ ip link show

# Habilitar/desabilitar interface
$ ip link set eth0 up
$ ip link set eth0 down
🗺️
Rotas e Gateway
BASH
# Ver tabela de rotas
$ ip route show
$ ip r

# Saída típica:
default via 192.168.1.1 dev eth0     # Gateway padrão
192.168.1.0/24 dev eth0 proto kernel # Rede local

# Legado
$ route -n
$ netstat -r

# Adicionar rota estática
$ ip route add 10.0.0.0/8 via 192.168.1.1

# Remover rota
$ ip route del 10.0.0.0/8
📡
Diagnóstico de Conectividade
BASH
# Ping básico
$ ping google.com
$ ping -c 4 8.8.8.8       # 4 pacotes
$ ping -i 0.5 192.168.1.1  # Intervalo 0.5s

# Traçar rota (traceroute)
$ traceroute google.com
$ traceroute -n google.com  # Sem resolver DNS
$ mtr google.com            # Combinação ping+traceroute

# Checar DNS
$ nslookup google.com
$ dig google.com
$ dig google.com A          # Só registros A
$ dig @8.8.8.8 google.com  # Usar DNS específico
$ host google.com           # Simples
🔌
Portas e Conexões Ativas
BASH
# ss — substituto moderno do netstat
$ ss -tulpn         # TCP+UDP+listening+pid+numerico
$ ss -tnp           # Só TCP com processos
$ ss -s             # Estatísticas resumidas
$ ss -4 state established  # Conexões TCP estabelecidas

# netstat (legado, ainda muito usado)
$ netstat -tulpn    # TCP+UDP ouvindo
$ netstat -an       # Todas as conexões
$ netstat -antp     # Com PID/processo

# Ver quem usa uma porta específica
$ ss -tulpn | grep :443
$ lsof -i :8080

# Ver conexões de um processo
$ lsof -p 1234 -i
🚨 No SOC: use ss -tnp para identificar processos com conexões suspeitas (portas altas, IPs externos inesperados = possível malware ou backdoor ativo).
🌐
Configuração de Rede (NetworkManager / ip)
BASH
# Adicionar IP à interface
$ ip addr add 192.168.1.50/24 dev eth0

# Ver ARP table
$ ip neigh show
$ arp -n

$ ip neigh flush all

$ cat /etc/resolv.conf

$ cat /etc/hosts

$ nmcli device status

🔥
Firewall com iptables e nftables
BASH — iptables
# Ver regras atuais
$ iptables -L -n -v
$ iptables -L -n --line-numbers

# Bloquear IP específico
$ iptables -I INPUT -s 1.2.3.4 -j DROP

# Permitir porta 22 (SSH)
$ iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Bloquear porta de saída
$ iptables -A OUTPUT -p tcp --dport 4444 -j DROP

# Salvar regras (Debian/Ubuntu)
$ iptables-save > /etc/iptables/rules.v4

# UFW (frontend simplificado)
$ ufw status verbose
$ ufw allow 22/tcp
$ ufw deny from 1.2.3.4

Ferramentas de Análise
As ferramentas mais usadas em um SOC para análise de tráfego, descoberta de hosts e investigação de rede.
🦈
Wireshark
GUI · Análise de PCAP
Analisador de protocolos gráfico. Captura e analisa pacotes em tempo real. Padrão da indústria para investigações de rede.
Filtros Wireshark
ip.addr == 192.168.1.1
tcp.port == 443
http.request.method == "POST"
dns.qry.name contains "evil"
tcp.flags.syn == 1
!(arp or icmp or dns)
🎯
tcpdump
CLI · Captura em servidor
Captura de pacotes via linha de comando. Essencial em servidores sem GUI. Salva em formato PCAP para análise posterior.
BASH
# Capturar toda interface
tcpdump -i eth0

# Filtrar por host e porta
tcpdump -i any host 1.2.3.4 and port 443

# Salvar em arquivo
tcpdump -i eth0 -w captura.pcap

# Ler arquivo salvo
tcpdump -r captura.pcap -n

# Mostrar conteúdo ASCII
tcpdump -i eth0 -A port 80
🗺️
Nmap
CLI · Scanner de rede
Scanner de portas e serviços. Fundamental para inventário de rede e identificação de ativos. No SOC, é base para Threat Hunting.
BASH
# Scan básico
nmap 192.168.1.0/24

# Detectar versão e OS
nmap -sV -O 192.168.1.1

# Scan furtivo (SYN)
nmap -sS -T2 192.168.1.1

# Portas específicas
nmap -p 22,80,443,3389 192.168.1.0/24

# Saída em XML p/ SIEM
nmap -oX scan.xml 192.168.1.0/24
⚠ Use apenas em redes autorizadas. Nmap gera alertas em qualquer IDS/SIEM decente.
⚡
netcat (nc)
CLI · Canivete suíço TCP/UDP
Utilitário versátil para leitura/escrita em conexões TCP/UDP. Usado para testes de conectividade, transferência de arquivos e debugging.
BASH
# Testar conectividade porta
nc -zv 192.168.1.1 443

# Banner grabbing
nc 192.168.1.1 22

# Escutar em porta
nc -lvp 4444

# Transferir arquivo
# Receptor:
nc -lvp 9999 > arquivo.txt
# Sender:
nc 192.168.1.10 9999 < arquivo.txt
🔬
Zeek (Bro)
NSM · Network Security Monitor
Framework de análise de tráfego orientado a logs estruturados. Gera logs por protocolo (http.log, dns.log, conn.log) — integra com SIEM.
Logs Zeek
# conn.log   → todas as conexões
# dns.log    → queries DNS
# http.log   → tráfego HTTP
# ssl.log    → handshakes TLS
# files.log  → arquivos transferidos
# notice.log → alertas Zeek

# Rodar Zeek em PCAP
zeek -r captura.pcap
🔍
Suricata
IDS/IPS · Detecção de ameaças
Motor de IDS/IPS de alta performance. Analisa tráfego contra regras (Emerging Threats, ET Open) e gera alertas em formato EVE-JSON.
BASH
# Testar PCAP com regras
suricata -r captura.pcap -l /tmp/

# Modo IDS em interface
suricata -i eth0

# Ver alertas EVE-JSON
cat /var/log/suricata/eve.json | \
  jq 'select(.event_type=="alert")'

Operações de SOC
O que faz um analista SOC, como redes se conectam ao trabalho diário e os alertas mais importantes para monitorar.
🏢
O que é um SOC?

O Security Operations Center (SOC) é o time responsável por monitorar, detectar, analisar e responder a incidentes de segurança 24x7. Trabalha com:

  • ◈
    SIEM (Splunk, Elastic, QRadar) — Correlação centralizada de logs
  • ◈
    EDR/XDR (CrowdStrike, SentinelOne) — Proteção de endpoints
  • ◈
    SOAR — Automação de resposta a incidentes
  • ◈
    Threat Intelligence — IoCs, TTPs, feeds de ameaças
  • ◈
    Análise de Rede — PCAP, NetFlow, firewall logs
🚨
Alertas de Rede no SOC

Os alertas mais críticos que chegam ao SOC via monitoramento de rede:

  • 🔴
    Port Scanning — Múltiplas portas varridas em curto intervalo. Indica reconhecimento.
  • 🔴
    Beaconing C2 — Conexão periódica e regular a IP externo suspeito (ex: a cada 60s).
  • 🔴
    Exfiltração — Grande volume de dados saindo para destino incomum.
  • 🟡
    Brute Force SSH/RDP — Múltiplas tentativas de autenticação falhas.
  • 🟡
    DNS Tunneling — Consultas DNS anômalas, subdomínios longos ou randômicos.
  • 🟡
    Lateral Movement — Conexões SMB/RDP entre hosts internos incomuns.
  • 🟢
    Tráfego em porta não-padrão — HTTP em porta 8888, SSH em porta 2222, etc.
🔍

NetFlow — Análise de Fluxo

NetFlow/IPFIX captura metadados de fluxos de rede (sem payload). Essencial para detecção de anomalias em grande escala.

Campos NetFlow
src_ip      → IP de origem
dst_ip      → IP de destino
src_port    → Porta de origem
dst_port    → Porta de destino
protocol    → TCP/UDP/ICMP
bytes       → Volume de dados
packets     → Número de pacotes
start_time  → Início do fluxo
end_time    → Fim do fluxo
tcp_flags   → Flags TCP usadas
🎯
IoCs de Rede — O que Buscar

Indicators of Compromise (IoCs) são artefatos que indicam comprometimento:

  • →
    IPs maliciosos — Checar em VirusTotal, AbuseIPDB, Shodan
  • →
    Domínios DGA — Domain Generation Algorithm (ex: xk3h9abc.com)
  • →
    User-Agents suspeitos — curl, python-requests em prod = suspeito
  • →
    JA3/JA3S hash — Fingerprint TLS de cliente/servidor. Detecta Cobalt Strike!
  • →
    Portas incomuns — HTTPS em porta 4444, 8443, 8080
  • →
    Long connections — Sessão TCP aberta por horas = possível C2 keep-alive

Análise de Logs

Logs Essenciais no Linux
Localização de Logs
# Logs de sistema
/var/log/syslog        # Ubuntu/Debian
/var/log/messages      # CentOS/RHEL

# Autenticação (SSH, sudo, login)
/var/log/auth.log      # Debian/Ubuntu
/var/log/secure        # CentOS/RHEL

# Kernel e hardware
/var/log/kern.log
$ dmesg | grep -i network

# Firewall (iptables com log)
/var/log/ufw.log
$ grep "UFW BLOCK" /var/log/ufw.log

# journald — sistema moderno
$ journalctl -u sshd --since "1 hour ago"
$ journalctl -f            # Tail em tempo real

Análise de Auth.log — Detectar Brute Force
BASH — Investigação SSH
# Ver falhas de autenticação SSH
$ grep "Failed password" /var/log/auth.log

# Contar tentativas por IP
$ grep "Failed password" /var/log/auth.log | \
  awk '{print $11}' | sort | uniq -c | sort -rn | head

# Logins bem-sucedidos
$ grep "Accepted password\|Accepted publickey" \
  /var/log/auth.log

# Sessões SSH ativas agora
$ w
$ who
$ last | head -20

# Usuários criados recentemente
$ grep "useradd\|groupadd" /var/log/auth.log
🚨 Mais de 10 "Failed password" do mesmo IP em menos de 1 minuto = Brute Force ativo. Acione o bloqueio via fail2ban ou regra de firewall imediata.

grep, awk, sed para Análise de Logs
BASH — Parsing de Logs
# Filtrar por IP específico em qualquer log
$ grep "1.2.3.4" /var/log/nginx/access.log

# Logs da última hora
$ journalctl --since "1 hour ago"

# Top 10 IPs em nginx access.log
$ awk '{print $1}' /var/log/nginx/access.log | \
  sort | uniq -c | sort -rn | head -10

# Top User-Agents
$ awk -F'"' '{print $6}' /var/log/nginx/access.log | \
  sort | uniq -c | sort -rn | head

# Erros 4xx e 5xx
$ awk '$9 ~ /^[45]/' /var/log/nginx/access.log

# Monitorar log em tempo real
$ tail -f /var/log/syslog | grep -i ssh

# Buscar em logs comprimidos
$ zgrep "Failed" /var/log/auth.log.*.gz

Formato de Log Apache/Nginx
access.log — Combined Format
1.2.3.4 - user [24/May/2026:10:15:30 +0000] \
  "GET /admin/login HTTP/1.1" 200 1234 \
  "-" "Mozilla/5.0 ..." 0.042

# Campos:
# $1  → IP de origem
# $4  → Data/hora
# $7  → URI requisitado
# $9  → Status HTTP
# $10 → Bytes enviados
# $11 → Referrer
# $12 → User-Agent

# IOC: brute force em /admin
$ grep '"POST /admin' access.log | \
  awk '$9==401' | awk '{print $1}' | \
  sort | uniq -c | sort -rn

fail2ban — Bloqueio Automático
BASH — fail2ban
# Status geral
$ fail2ban-client status

# Status da jail SSH
$ fail2ban-client status sshd

# IPs banidos atualmente
$ fail2ban-client status sshd | grep "Banned IP"

# Banir IP manualmente
$ fail2ban-client set sshd banip 1.2.3.4

# Desbanir IP
$ fail2ban-client set sshd unbanip 1.2.3.4

# Log do fail2ban
$ tail -f /var/log/fail2ban.log

QUESTÃO 01Em qual camada do modelo OSI o protocolo IP opera?
✓ Correto! O IP opera na Camada 3 (Rede), responsável pelo roteamento e endereçamento lógico entre redes diferentes.
QUESTÃO 02Qual é o range de IPs privados definido pela RFC 1918 para redes de Classe A?
✓ Correto! O range 10.0.0.0/8 é a faixa Classe A privada. O 169.254.0.0/16 é APIPA (sem DHCP) — sempre suspeito em ambiente corporativo.
QUESTÃO 03Um analista SOC observa múltiplas conexões TCP com SYN sem ACK de resposta. O que isso provavelmente indica?
✓ Correto! SYNs sem ACK de resposta indicam SYN Flood (DDoS) ou scan de porta -sS do Nmap. Ambos são eventos que devem gerar alertas no SIEM.
QUESTÃO 04Qual comando Linux mostra todas as portas em estado de escuta (listening) com o PID do processo responsável?
✓ Correto! ss -tulpn: -t (TCP), -u (UDP), -l (listening), -p (processes/PID), -n (numérico). Essencial para identificar backdoors em servidores.
QUESTÃO 05Qual protocolo pode ser usado para exfiltração de dados através de um firewall que bloqueia todo tráfego exceto DNS?
✓ Correto! DNS Tunneling usa consultas DNS (geralmente permitidas) para encapsular dados. Ferramentas: iodine, dnscat2. Detecte pelo volume anômalo e tamanho de queries DNS.
QUESTÃO 06Em qual arquivo do Linux você encontra os registros de tentativas de autenticação SSH no Ubuntu?
✓ Correto! O /var/log/auth.log no Debian/Ubuntu registra toda autenticação. Use grep "Failed password" para detectar brute force.
QUESTÃO 07O que é ARP Poisoning e qual o principal risco para a segurança?
✓ Correto! ARP Poisoning associa o MAC do atacante ao IP do gateway, fazendo todo tráfego LAN passar por ele — Man-in-the-Middle completo. Detecte com ARPwatch ou XDR.
QUESTÃO 08Qual porta TCP está associada ao protocolo SMB e foi explorada pelo ransomware WannaCry via EternalBlue?
✓ Correto! A porta 445 (SMB) foi o vetor do WannaCry (2017) via exploit EternalBlue (MS17-010). No SOC, qualquer tráfego SMB externo deve ser imediatamente investigado.
